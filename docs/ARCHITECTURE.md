# Current Architecture

This describes the repository as it exists now, not the intended finished design. The project uses Godot 4.7.2 stable (`project.godot` declares the Godot 4.7 / Forward Plus feature family), with one runtime-composed main scene and vendored GUT coverage for run state, generation, cards, and statistics. The game version remains `0.1.0-alpha`. Earlier consolidation verification used Godot 4.6.2; those historical results do not establish verification on 4.7.2.

## Runtime Shape

`scenes/main.tscn` contains a `Node2D` with `scripts/main.gd`. At startup, `main.gd` creates the camera, ball, level builder, HUD, menu, shop, and tutorial manager in code. `scenes/golf_ball.tscn` is the only substantive reusable scene; its script owns input and ball behavior. Course geometry and most UI are not authored scene trees.

```text
main.gd (composition, local signal wiring and lifecycle coordination)
├─ run_state.gd (scene-local run authority, guarded phases, cards/effect cache)
│  ├─ run_stats.gd (single cumulative ledger and copied history)
│  └─ card_effect_resolver.gd / active_card_curse.gd (existing typed rules)
├─ golf_ball.gd (input, aiming, flat physics, discrete elevation, sink/reset)
│  ├─ ball_motion.gd (bounded static sweep and shared discrete damping)
│  ├─ trajectory_predictor.gd (deterministic resting-position forecast)
│  └─ trajectory_renderer.gd (biome-aware dotted presentation)
├─ feedback_director.gd (shared shot, movement, terrain, cup, and transition VFX)
├─ course_camera.gd (BALL_FOLLOW / COURSE_OVERVIEW, sole framing and zoom owner)
├─ audio_controller.gd (crossfaded themes/ambience, pooled physical SFX, and high-speed swoosh)
│  └─ audio_cue_catalog.gd (semantic assets and shared mix/guard tuning)
├─ hole_generator.gd ← biome_database.gd / biome_profile.gd
│  ├─ course_motifs.gd (spatial vocabulary and biome design emphasis)
│  ├─ course_grammar.gd (ephemeral route-first candidate composition)
│  └─ course_quality.gd (pure deterministic geometry heuristics)
├─ level_builder.gd ← generated definitions / level_database.gd fallback / tutorial_database.gd
│  ├─ course_visual_factory.gd (shared pixel materials, sprites and continuous edge presentation)
│  ├─ gameplay_hazard.gd / moving_hazard.gd / elevation_ramp.gd
│  ├─ hazard_telegraph.gd (presentation-only moving-hazard timing/path cues)
│  └─ biome_ambience.gd (course-anchored pixel scenery and independent ambient motion)
├─ shop_manager.gd ← typed card_database.gd definitions / difficulty_profile.gd
│  └─ shop_presentation.gd
├─ tutorial_manager.gd (ball, point-resolver and copied effect-presence interface)
├─ release_hud.gd / transition_presentation.gd
│  └─ ui/ (shared style, icons, backdrop, logo, action button, card, run setup, settings, title-attract, and history components)
├─ difficulty_database.gd / difficulty_profile.gd
├─ game_settings.gd / seed_codec.gd / hole_rating.gd
└─ ui/power_meter.gd (presentation-only shot readout)
```

Signals carry ball completion and hazard contacts from the ball/builder into Main, and shop/tutorial intents back into its lifecycle coordinator. Main still composes the existing UI and owns live node references and terrain integration; it does not duplicate run accounting or implement audio, card resolution, generation or VFX. No additional RunController wrapper, global event bus, autoload state or framework is introduced.

## Systems

- **Ball:** `RigidBody2D` retains native shape-cast CCD and normal movement tuning. Its `_integrate_forces` backstop sweeps completed travel against static boundaries using `BallMotion`, with at most eight impacts and remaining-time consumption. It rejects impossible native positional-separation jumps against a velocity/delta travel budget, without reducing legitimate impulse. Pad exit separation also sweeps. Native physics still owns moving-body contacts. Mouse/keyboard input, card modifiers, stopped-frame detection, discrete `-1/0/1` masks, ice, tee, pause and sink/reset remain local. `TrajectoryPredictor` uses the same discrete damping and sweep, world damping, known sand/ice and Area2D's one-step notification delay; its tip is the final simulated resting position. Forecasts assume current elevation/static walls; moving gates, ramps, wind and pads may change the result.
- **OOB accounting:** Main watches playable-surface containment and owns the cancellable three-second recovery. `RunState.record_accepted_shot` issues a monotonic per-shot refund ticket and records one stroke in both ledgers. Only automatic OOB recovery may consume that ticket once on the same active hole. Finishing inside, ordinary hazard/manual reset, resolution or new-hole/run cleanup invalidates it. Recovery precedes ceiling resolution; warnings derive from `RunState.remaining_shots`, not independent HUD arithmetic.
- **Feedback:** `FeedbackDirector` consumes semantic stopped, wall-impact, terrain, hazard, cup, and progression events. It owns transient primitive shapes, yellow stop confetti, a bounded sampled trail, clamped camera response, screen flashes, and named duration/intensity exports; it never changes collision or shot outcomes. `GameAudioController` crossfades eight original musical themes and six ambience beds, plays pooled physical event/UI cues through SFX, and permits only a bounded high-speed swoosh—there is no normal rolling loop.
- **Biomes:** Six `BiomeProfile` instances contain identifiers, display names, terrain/background palettes, decoration identifiers, hazard weights, generator difficulty values, and ambience identifiers. They are data consumed by shared systems, not separate gameplay implementations.
- **Levels:** `HoleGenerator` preserves its public dictionary API, eight-candidate budget, validator boundary and `LevelDatabase` authored fallback. `CourseMotifs` supplies 26 route/challenge/approach components. `CourseGrammar` is an ephemeral `RefCounted` candidate builder: choose an identity-stable idea, transform/stretch its route, reserve landing zones, add optional branches/elevation, place route-relative guards, then find an unoccupied primary path. `CourseQuality` scores actual geometry, broad shot envelopes, recovery, direct-line pressure, approximate shot count and density. The first highest valid score at or above 72 wins. No global RNG or full physics simulation is involved. Biome `generator_difficulty` now supplies live `section_stretch`, `recovery_radius` and per-difficulty lane radii rather than unused legacy rectangular-map dimensions.
- **Generation challenge:** Grammar revision 3 resolves `GenerationChallenge` once from difficulty, overall progress, biome design, local arc and generation curses. It drives cluster shape/count, blockers, mover/second-mover chance, branches, elevation, stretch and recovery without weakening safety. Every reservation checks primary-route and free-surface recovery before acceptance; rejected partial cluster members cannot leave false cluster metadata. Quality challenge-fit compares authored guard sections with that resolved budget. Corpus reports include both curse-inclusive and no-curse difficulty/stage aggregates.
- **Construction:** `LevelBuilder` converts generated 100-pixel grid cells into palette-driven floor, oversized background surround, substantial collision bounds, elevation surfaces, ramps, lower course areas, bridges/overpasses, tee, cup/flag, static and moving hazards, telegraphs, decorations, and blockers at runtime. The cup's clipped putting region uses the same square floor cells and alternating biome detail with `green_a`/`green_b` palette variants; no separate putting overlay exists and physics remain unchanged. Lower cells reuse alternating normal biome tiles with perimeter depth edges and a higher-wall shadow. The active elevation stays at full contrast while other layers remain recognizable but attenuated. Reusable hazard nodes own deterministic collision behavior; `CourseVisualFactory` and bounded `BiomeAmbience` own presentation only.
- **Validation:** `LevelValidator` checks the builder schema and actual placement footprints independently of generator reservations. Grammar-revision-2 checks additionally require a contiguous design route, honest shot-corridor widths, a primary path inside the main corridor, clear 3×3 tee/cup/recovery footprints, fulfilled curse counts, connected 1–5-cell formations, reachable free surfaces/branch escapes, wide elevation surfaces, clear ramp landings and a safe initial bounce runway. Pendulum bounds include the downward arc; rotating-rod bounds cover every orientation. Numeric/motion bounds are checked before footprint iteration. Overpasses require both surfaces, a connected one-to-two-cell tunnel and at most one crossing. `validate_level(..., report_errors=false)` supports quiet candidate rejection; `generation_errors` exposes design failures after the base schema is valid. `main.gd` still revalidates after card modifiers and before construction.
- **Run flow:** Scene-local `RunState` owns seed/difficulty, current index (biome/local/overall indices are derived), strokes/time, currency, level definitions, owned cards, active curses and resolved effects. Its `RunStats` is the sole cumulative stroke/card/history ledger. `transition_to` rejects repeats and illegal transitions; `PREPARE_HOLE` and `HOLE_RESOLVING` make construction and asynchronous resolution explicit alongside the existing menu/start/intro/play/results/shop/ending phases. Main coordinates transitions and nodes. `RunSetupScreen` collects difficulty/seed intents, `SeedCodec` validates them, `DifficultyDatabase` supplies unchanged profiles, `HoleRating` computes unchanged ratings, and `GameSettings` persists wired options.
- **Shop:** The difficulty profile supplies seeded offer/purchase limits: Easy 4/2, Normal 5/3, and Hard 6/5. Four, five and six offers use one tall row. Four offers share a side details panel; five/six use a lower details strip. No placeholder slots are added. Unaffordable cards remain readable but disabled and Skip / Continue is available. The tutorial passes an explicit deterministic four-card pool and requires exactly the demonstrated minimum purchase before continuation. Production shops appear after biomes 1–5.
- **Card effects:** `CardDefinition` owns typed identity, price, human-facing disclosures, stacking text, separate `CardEffectSet` bonus/curse values, and curse duration. `CardEffectResolver` additively resolves persistent bonuses unchanged while multiplying curse values by the active difficulty profile, then applies release safety clamps. RunState stores and advances each curse once when Main accepts a hole resolution. ShopManager's production wallet forwards to that same RunState; standalone presentation/test shops retain a private wallet. Eligibility and deduction stay in ShopManager, not UICard.
- **Rarity:** `CardRarityProfile` creates independent Common/Rare/Epic/Legendary offers with category-aware benefit/curse progression, ceiling-safe relief/counts, rounded cost and 3/3/4/5-hole curses. The production shop's separate seeded rarity stream does not reorder base identities. Tutorial pools remain explicit Common cards. `UICard` renders the authoritative rarity, effect descriptions, cost and duration; it calculates no balance.
- **Tutorial:** Six fresh deterministic definitions carry the actual Meadow palettes/ambience. Sand/water lessons start with a 100×600 transverse band; after the first authoritative water reset, `LevelBuilder.open_tutorial_water_lane` replaces only the flagged tutorial water footprint with 100×200. A new tutorial restores the full band. `TutorialManager.hud_concepts()` exposes score/coin/effect introduction state to `ReleaseHUD`, not gameplay rules. Its guarded lifecycle clears coach, skip button, world highlight and tweens on exit. Completion/Skip return to Main Menu without generating a real run. Only the shop lesson opens a shop. Completion remains stored in `user://tutorial_complete.cfg`.
- **Presentation UI:** `release_theme.tres` and `UIStyle` centralize approved Jersey 10 for all ordinary text, thin pixel panel rims, semantic ink and readable role sizes. `UILogo` draws the byte-identical approved export from `assets/brand/approved_wordmark.png`. Native `UIActionButton`, `UICard`, `ReleaseHUD`, `ShopPresentation` and `TransitionPresentation` render the production treatment; there is no sample adapter in the normal runtime. `IconCatalog` retains eight cartoon equipment textures in a bounded strong cache, with unchanged card IDs and tutorial aliases; `CardIllustration` shares those complete square assets across offers/details/rails. The native shop owns hover/focus details and explicit Buy controls while ShopManager alone owns purchases. Title cursor parallax remains; pause freezes the actual course. Settings, run setup, tutorial, history and VS read the same typography/components. Presentation calculates no prices, effects, scores, generation or progression.
- **Appearance:** scene-local `UIAppearance` adapts the shared Theme and canonical local overrides using `UIStyle` semantic colors. Weak node references/deferred instance IDs handle dynamically replaced cards safely. Glyphs retain their own canonical ink across reparenting; palette notifications have one adapter connection. Native dropdown/selection masks receive dark ink once when the shared light Theme is built. Only controls under Main's HUD CanvasLayer participate; collectible/postcard art and the world stay authored. `UILogo` preserves the approved raster artwork in both appearance modes; only surrounding UI ink changes. `UIBackdrop` resolves changing backgrounds through the same palette. `GameSettings.ui_appearance` persists Dark (default) or Light. `PowerPalette` is shared by the meter and pullback gradient.
- **Telemetry:** `RunStats` tracks strokes, cards, hazards, resets, elapsed play time, and immutable per-hole history snapshots, then prints a summary when Hole 18 reaches run results. Its history API exposes only completed holes and the current hole; future holes remain locked.

### Visual-overhaul integration boundaries

- `UIStyle` owns reusable paper, clipped-ticket, fixture, and semantic styles. `CardIllustration` composes the same catalog equipment glyphs used by card headers; `CoursePostcard` supplies biome prints and the final trophy seal to `TransitionPresentation`. These controls read existing data and introduce no gameplay state. `tools/build_brand_assets.py` is the editable vector source (including archived Fredoka wordmark outlines and palette-derived semantic glyph ink); `tools/export_brand_rasters.gd` deterministically derives app PNGs/ICO through Godot. Neither tool ships or runs in gameplay.
- `CourseCamera` extends the existing Camera2D boundary and solely owns position/zoom with `BALL_FOLLOW` and `COURSE_OVERVIEW` states. Exported tuning is `gameplay_zoom = 1.25`, `follow_speed = 28`, `max_follow_lag_pixels = 36`, `transition_duration = 0.35`, and `overview_padding = 64` world units. Follow uses exponential smoothing with a logical-screen-distance cap and no elevation or cup bias. Transitions interpolate position and zoom with smoothstep easing in real seconds, even at VS watch speed; their return destination follows the live ball. Reduced Motion removes follow lag/cup emphasis and shortens transitions to 0.15 seconds.
- `LevelBuilder.get_playable_bounds()` reads the built, validated definition and all occupied elevation cells; unions cell footprints plus wall thickness, tee, cup/flag, obstacles, static hazards and moving hazard travel; then transforms the result into world space. It never measures scenery or unused map allocation. Main passes that rectangle when loading a hole or handing the course to the AI. `ReleaseHUD.get_course_view_rect()` provides logical HUD-safe space, and Main additionally reserves the tutorial coach / VS watch bar. Resize or HUD layout changes smoothly recompute the overview fit. Zoom is the smaller safe-width/course-width and safe-height/course-height ratio, capped at gameplay zoom; there is no course-size-dependent normal zoom.
- Tab and the HUD button invoke one Main intent. Camera state changes refresh the HUD, cancel aiming through the existing `GolfBall.set_input_enabled(false)` path, and gate player shots. OOB and hazard cleanup use the same gate. Simulation/timers remain active, including externally controlled AI shots. Main clears overview on resolution/reset/new hole/new run; pause preserves framing. `FeedbackDirector` owns only the transient camera offset and suppresses it during overview. Cup feedback emits an emphasis request to CourseCamera, which composes it with framing and clears it on lifecycle reset. Physics, generation, geometry and shot conversion retain their existing owners.
- `Main` and its HUD layer publish the existing reduced-motion preference as presentation metadata. Shared controls inherit it; transient feedback uses its existing settings boundary. Surface ripples/launch energy and ambience use bounded 24 Hz redraws and stop decorative motion when reduced motion is enabled. Functional hazard simulation and telegraph timing are unchanged.

- `UIValueTicket` owns the nested label/value well and cancellable fade/vertical-slide transition. `SeedTicket` emits copy intent and owns temporary confirmation; `HoleHistorySelector` holds defensive history snapshots and emits selection intents, with wheel/key navigation and adjacent played-hole previews. `UIToggle` normalizes all checked/unchecked style states and synchronizes its On/Off label, including silent settings refreshes. `SettingsScreen` shows one hover/focus description in its footer. Title parallax reads viewport mouse events, not desktop cursor polling, so stretch/embedding use the same coordinate space.
- `BiomeAmbience` composes eight asymmetrical seeded groups on exposed course edges, with fixed prop anchors and bounded secondary motion. LevelBuilder passes read-only occupied-cell rectangles to this presentation node; merged dark banks beneath roots have no collision. Its private random stream cannot affect generation or AI. LevelBuilder skips its old extra decoration scatter when this ambience owns the surround. Wall rims sample continuous original illustrated strips over exposed runs, with joined interiors suppressed and unchanged physical bounds.
- Player trajectory requests omit collision queries and reuse deterministic damping/terrain equations for an uninterrupted straight-line stop. AI keeps its internal static sweep. `BallMotion.reflect_velocity` reflects then applies uniform restitution; GolfBall's static-wall CCD backstop uses pre-contact velocity instead of a native friction-flattened result. `reset_to` queues the requested transform for `_integrate_forces`, preventing stale physics state from overwriting a reset; an immediately accepted shot is preserved. Moving AnimatableBody2D contacts remain native.
- `LevelBuilder` supplies cosmetic neighbor connectivity to surface art so exposed hazard banks join continuously. Elevation-root `modulate` propagates active/inactive contrast to the complete art subtree; it does not alter physics masks. Background landmarks and material detail remain non-interactive.

### Approved production pixel integration (2026-09-24)

The owner explicitly authorized normal-game rollout after the reference slice. `project.godot` still launches `scenes/main.tscn`; no visual flag, sample scene, fixture geometry or audio audition is injected. Production raster assets live in `assets/world/`, `assets/presentation/cards/`, `assets/ui/panels/`, `assets/brand/` and the Jersey font directory. Historical sample code/assets and references are preserved but excluded from exports.

`LevelBuilder` keeps its native bodies, shapes, cell/elevation data and seeded hazard setup. It chooses raster surfaces through `presentation/world_art.gd`, joins material walls without cell seams, and adds presentation-only surface, flag and pendulum nodes. `BiomeAmbience` owns fixed scenery anchors outside the course and independent particles; `WorldDistance` draws seamless repeating distant/middle layers with separate camera-response rates. The only tee owner remains LevelBuilder: one cropped tee seat at the native start, hidden on `tee_left`, restored by `restore_tee()` on manual reset or competitor reset. `GolfBall._create_ball_art` draws a centered ball-only sprite at the collision diameter; other ball functions remain unchanged.

Font import disables system fallback; unsupported UI triangle glyphs use supported text or semantic icons. Production music/SFX code, audio files and bus behavior are unchanged.

## Current Content and Rules

- Eighteen generated production holes: Meadow, Desert, Autumn, Snow, Swamp, and Volcanic, with introductory/normal/hardest progression inside each biome.
- Mechanical hazards implemented through shared contracts: sand, water/lava reset areas, ice, direction pads, seeded circular bounce pads with swept-circle detection and bounded minimum/multiplier/maximum exit tuning, blockers, pendulums, falling ice, and rotating fire rods. Rough grass is visual-only; legacy mechanical rough and red/out penalty tiles are rejected.
- Falling ice begins as a detector plus shadow, drops once when entered, enables collision only when landed, and remains until rebuild; landing on the ball and active pendulum/fire-rod contacts relay through the existing authoritative reset signal. Pausing freezes their level-root simulation.
- Cards implemented: Overdrive Driver, Rangefinder Lens, Sand Cleats, Heavy Core, Lucky Putter, Power Club, Coin Magnet, and Gust Guard.
- Starting currency and score-based rewards match the intended 2/3/2/1/0 structure, but the code calls currency “tokens.”
- Card bonuses stack for the run. Common/Rare curses last three resolved holes, Epic four and Legendary five, including across biome boundaries; the HUD/interstitials show remaining duration. Power Club and Gust Guard pass bounded direction-zone counts through `apply_hazard_modifier`, which regenerates revision-3 candidates from original identity plus effect state. Legacy/authored fallback definitions retain their modifier path. Cup curses scale subsequent cups while active. Base card effects, shop limits and scoring rewards remain unchanged; rarity and OOB refunds are the explicitly approved gameplay revisions.
- Hole results with one-to-five-star `HoleRating`, five biome shops, run results, a run grade, ending, and clean new-run reset are present. Par + 4 produces a one-star Stroke Limit outcome and safe advancement without a positive completion cue. Presentation uses primitive tweened feedback and original generated music/SFX; there is no adjusted speed score, GPU particle dependency, or randomized biome order.
- `R` preserves accepted current-hole strokes and elapsed time, resets transient hazards/audio coherently, and cannot refund score/reward cost. If the accepted-stroke count has reached par + 4, reset resolves the forced result instead.
- Opening the menu during a live shot freezes both the ball and level-root simulation. Resume restores the captured shot velocity and hazard cycle coherently without allowing behind-overlay collisions or state changes.

## Data Contracts

A normal level dictionary requires `map`, `start_cell`, `hole_cell`, `par`, `hazards`, and `obstacles`. Flat legacy definitions receive elevation-zero defaults. Generated definitions additionally carry static/moving hazards, ordered `main_route_cells`, optional `branches`, `elevation_cells`, `elevation_transitions`, `elevation_structures`, tee/start/cup elevation, biome/local/overall indices, seed/attempt/fallback, difficulty profile, quality score/breakdown/candidate evidence, route-interaction metrics, cluster metadata, palettes, decorations, ambience, and visual rough cells. Revision 2 adds `grammar_version`, `generation_identity`, `generation_options`, `course_idea`, `selected_motifs`, `biome_arc`, `challenge_budget`, `lane_width_cells`, `design_route_cells`, `primary_corridor_cells`, `shot_corridors`, `shot_zones`, `placement_reservations` and `recovery_reservations`. Reservations are diagnostics, not trusted validation evidence. `candidate_scores` preserves each candidate's validity/score/reasons; rejected and below-floor counts, retry count and `fallback_reason` remain explicit.

Typed per-hazard fields cover direction, ice intensity, bounce seed/minimum exit speed/speed multiplier/maximum exit speed/cooldown, placement role, cluster identity/size, curse-added marker and moving timing/path data. `launch_target` is diagnostic only. Ramp transitions optionally specify `width` in world pixels (24–100, authored default 72); generated parallel ramps use 100 for continuous deck coverage. The existing `ElevationRamp` owns transitions and physics, unchanged. Active card generation adds `card_hazard_count` and `card_cup_radius_scale`; tutorial definitions retain lesson/step and deterministic-shop fields.

Revision 3 also exposes `generation_challenge`. Falling-ice definitions independently validate an exact 100×100 size; runtime setup enforces the same size for legacy callers. Pendulum root transforms update translation/rotation atomically so `AnimatableBody2D.sync_to_physics` cannot discard translation. Telegraphs follow the actual hazard through a weak reference and reappear after reset. Boundary segments have square joins and explicit outside corner fills; lower transition markers and sparse seeded blade/crack detail are presentation only.

`tests/procgen_inspector.tscn` is an explicit development-only scene displaying routes, occupied cells, recovery, active layers, candidate scores and replay inputs. It is never loaded by production Main. `tests/procgen_corpus.gd` writes machine-readable distributions and replayable feature examples to `user://procgen_overhaul_20260906/`; `tests/procgen_review.tscn` renders the actual builder across 108 base cases plus those feature examples.

Level dictionaries remain flexible and untyped, so adding level keys requires coordinated changes across the generator, validator, builder/controller, and documentation. Cards no longer use dictionaries: `CardDefinition`, `CardEffectSet`, and `ActiveCardCurse` form the typed economy boundary.

### Lifecycle, presentation and audio ownership

- Main's generation counter invalidates asynchronous cup/hazard continuations on manual reset, new hole, new run and an actual return to title. A live-hole menu is a pause overlay, not a fake MAIN_MENU phase: ball/level simulation freeze, elapsed time stops, and resume preserves the shot and hazard cycle. Resolving permits the sink animation but rejects new input and duplicate results.
- RunState is a fresh RefCounted instance per Main, not a shared mutable Resource. Its snapshot copies history, card-name arrays and nested ratings. The HUD receives copies; its intents do not calculate or mutate rewards/effects. Existing level dictionaries remain behind the unchanged generator/validator/builder boundary.
- Accepted ball/builder events are routed locally once. FeedbackDirector owns visual response only; it has no audio-request signal. AudioController owns sound choices. Dedicated reset-water/lava/sand and bounce events exclude their generic hazard echo. Falling-ice landing owns the impact sound; a later crush reset does not repeat it. Par+4 is determined before cup audio so a stroke-limit cup cannot play positive sink/completion cues.
- AudioCueCatalog centralizes assets, theme/ambience mapping, pool bounds, fades and cooldowns. AudioController has two Music players, two quieter ambience players on Music, ten SFX voices and one high-speed noise voice. Music changes use a cancellable 0.8-second crossfade; latest state wins. Repeating a state preserves its playhead. Pause keeps music moving with a small trim and stops swoosh; leaving a biome fades ambience. Results/ending reuse the title composition with distinct completion accents.
- Successful hole outcomes add one restrained recorded crowd applause; failure owns both supplied layers plus one disappointed crowd, cancelling/suppressing positive crowd/score cues. Accepted purchases use one baked physical chip/register cue; rejected purchases emit only error. The focused cue renderer and `playtest_audio_manifest.json` record verified CC0 inputs separately without touching the existing score or protected supplied files.
- Movement intensity is a pure smoothstep above 520 px/s, full at 1100 px/s, followed by smoothed gain. Low-speed movement is silent; reset/transition stops it immediately. Purchase/failure/final accents briefly duck music. Catalog SFX gain leaves 8 dB for overlapping events before user bus controls; the existing Master limiter is a safety net, not the normal loudness target. GameSettings applies Master/Music/SFX volume and mute through buses, never individual players. Boost cue cutoffs (0.60/0.82 of the launch cap) cover all three supplied samples across the actual minimum-to-maximum launch range; launch physics is unchanged.
- UI audio binds to Main's HUD subtree only, including later-created buttons, and disconnects on rebind/exit. Purchase/special-action buttons suppress the generic click. Failure plays both supplied layers together, suppresses positive cues, and clears that guard on the next hole.
- Cleanup stays local: GolfBall.reset_to cancels ball tweens/shot/trajectory state; LevelBuilder/hazards own dynamic resets; FeedbackDirector resets trail/particles/camera; ShopManager resets card/coin/curse tweens; TutorialManager clears coach/highlight; TransitionPresentation cancels arrival and history tweens; AudioController clears voices/loops. Main invokes these boundaries instead of editing internal nodes.
- GolfBall has its own sink-generation token to reject queued animation starts after reset. Finished callbacks, rather than awaiting a tween that may be killed, avoid retaining cancelled tweens. Shop card slots refit their child anchors after container layout, preventing an initial minimum-size offset from surviving an intro/purchase animation. Neither fix changes animation duration, pricing or input rules.
- The score/sample renderer is development-only. Runtime loads finished WAVs; downloads and Python never run in-game. Provenance and reproduction are in `AUDIO_SOURCES.md`; `assets/audio/audio_manifest.json` inventories the eight scores, cyclic noise ambience and protected supplied/sand cues.

## VS AI ownership and shared-course boundary

`Main` keeps the existing gameplay/event/accounting path. Scene-local `VsMatchController` coordinates turns and binds Main to the active golfer's `RunState`; `VsMatchState` holds the two private runs, hole comparisons and defensive copies of one frozen course per hole. Solo and Tutorial bypass the VS branch. No autoload, global event bus or alternate physics engine is introduced.

`MatchCourseRules` explicitly classifies every `CardEffectSet.Kind`. It gathers course effects from both builds, sorts contributions, adds them with the existing per-owner curse multiplier and clamps once. `VsMatchState.prepare_course()` passes this resolved configuration into HoleGenerator once, applies the shared cup scale, validates, then caches it for both golfers. A repeated request returns a copy; AI turn setup never calls generation. Invalid shared definitions fail closed instead of producing a private fallback. Personal modifiers remain in the existing owner-specific resolver. A prospective-card argument permits read-only AI evaluation of the *marginal* shared cost, including already-saturated clamps.

`LevelBuilder.reset_for_competitor()` retains the course instance/definition and invokes the existing local reset owners. Moving hazards restore seeded phase and armed ice; pads clear trigger counters/cooldowns; ramps clear tracked bodies; telegraphs reset; the tee and active layer return to their starting state. Main clears transient feedback, audio, OOB tracking and terrain sources, swaps the private run, and resets the actual GolfBall to the tee. The preparation phase pauses simulation while queued area-exit notifications drain; generation tokens invalidate cancelled turn handoffs. Personal ball parameters are reapplied on *both* owner changes. Curse expiry cannot mutate an already-frozen course.

`AIDifficultyProfile`, `AIShotPlanner` and `AICourseModel` are bounded scene-local decision helpers. The query-only physics body has collision layer zero and queries the same elevation masks/`BallMotion` static solver; it never moves or collides with the actual ball. Forecasts include terrain, wind, discrete ramps, deterministic pad output and observed mover phase. A tile-distance field supplies useful route/landing targets, not physical reachability guarantees. Coarse candidates and real-timestep finalists receive bounded lookahead and, for stronger tiers, an execution-error safety envelope. Seeded errors and private control modifiers affect the selected intent, submitted through `GolfBall.shoot_normalized()` → existing `shoot()`. Only real gameplay events determine results.

Beginner/Intermediate have 8/12 angle samples, 3/4 power samples, 17°/9° bounded aim error, 34%/21% power error, 0 next-shot probes and 0.12/0.07 approach-power quantization. Higher tiers retain increasingly dense bounded planning. `VsMatchController` eases external aim/power during the last profile-owned preparation interval of its existing shot delay; no ball transform or hazard timeline changes. Reduced motion shows the selected aim immediately.

`VsPresentation` reads match state and emits intents using current Theme, icon and button components. `UICard` receives an optional VS disclosure flag. `ShopManager.try_purchase_card()` is the common authoritative wallet/eligibility transaction; the player's UI retains existing feedback, while `AICardPicker` independently consumes the same immutable offer definitions at shop-open. AI decisions are inspectable in the existing development-only debug HUD, never production UI.

Spectator speed scales `Engine.time_scale`, physics tick rate and maximum steps together, keeping the simulation delta at the original 1/60 second. VS scoring time advances in physics ticks, including think/wait time; Solo timing is unchanged. Pause, turn completion, cancellation, menu and node destruction restore the original engine clock. Skip is the same live simulation at 8×. ## Technical Constraints and Risks

- Main remains sizeable because runtime UI construction and mature terrain integration are deliberately retained. Accounting, card state, power-meter drawing and audio/VFX decisions are separated; further extraction needs a concrete benefit, not file-size aesthetics.
- Runtime-created UI uses shared presentation components and a common `release_theme.tres`. Containers and anchors own the primary layout. The configured `canvas_items` stretch keeps a 1920×1080 logical canvas across the four requested 16:9 window resolutions; compact branches use logical dimensions, not physical window pixels. `visual_overhaul_review` exercises real Main screens at 1280×720, 1600×900, 1920×1080, and 2560×1440, including full card disclosures, longest tutorial text, and a ten-digit seed. Existing 3440×1440 scenarios remain available, but older ultrawide evidence is not automatically evidence for the latest overhaul. Untested aspect ratios, localization expansion, and platform-safe-area behavior require dedicated checks.
- RunState's transition table is authoritative. Main's hazard-reset and transition-generation fields describe live node operations, not duplicated run results. Tests arrange isolated presentation snapshots directly; production uses guarded transitions. Debug HUD toggling is gated by `OS.is_debug_build()`; QA/inspector scenes and tools remain excluded by the Windows preset.
- Rendered audio and signal/loop measurements cannot establish listening comfort. Human approval of the eight arrangements, their balance, and supplied-asset redistribution provenance remains a release gate.
- Generated layouts validate a main route plus secondary branches and discrete transitions, but physical reachability, elevation readability, difficulty, and moving-hazard timing still require full human playtesting.
- Physics feel depends on engine settings and hard-coded tuning constants; changes require hands-on playtesting.
- The exported Windows executable and archive are build artifacts and may lag source. There is no Mac export preset despite the design target.
